# P56-T1 Practical Utility Benchmark

## Question and Decision

Does a source-investigating agent produce a complete SpecPM package that helps
a consumer discover and integrate software more accurately and efficiently
than the existing pipeline or the repository README?

This is a five-repository pilot, not evidence of universal quality. Phase 55
remains PARTIAL. Phase 56 can select a bounded next experiment or rollout; it
cannot retrospectively turn the old calibration into a PASS.

## Experimental Units

The companion evaluator-only benchmark contains five pinned revisions and
25 questions: discovery, integration, operations, limitations, and evidence
for each repository. The unit is the intended product described there, not
whichever nested package a manifest scanner selects first. Multiple
BoundarySpecs may describe that product when justified. Report missing product
coverage and boundary differences explicitly.

Arm A is the current pipeline, frozen at SpecHarvester commit
`67e5d26830fe716f3cbed77c3a10d30a5c621b0f`.
Arm B is investigative authoring using the repository-owned P56-T2 skill and
P56-T3 runner. Arm C is the pinned root README. Preserve original bytes and
full candidate sets; evaluation adapters may render them but cannot improve
content, manually merge claims, or hide failed candidates. Arm A combines its
static package and complete semantic proposal as separately identified draft
layers; it must not present a proposal as accepted YAML. Arm B supplies complete
candidate YAML. Report this representation difference. Arm A keeps its existing
principal-candidate selection (first eligible member package); record its
coverage limitations rather than retrospectively authoring a better baseline.
The complete-package adoption requirement applies to B, not to exclusion of A.

The primary endpoint compares end-to-end systems, not model intelligence.
Use one consumer envelope: product identity, unchanged content layers, and
source references. Separately report boundary coverage (correct product,
partial product, wrong member) and utility for questions whose facts fall in
both arms' actual boundaries. Never use that conditional score for adoption:
it excludes difficult cases and cannot replace the fixed denominator.

## Models and Budgets

Generation arms A and B use `gpt-5.3-codex-spark`, reasoning `low`, one initial
attempt and at most one failed-attempt retry. Each attempt permits one semantic
JSON repair, at most 300 seconds per model call and 600 seconds total including
repair. Each repository/arm has 1,200 seconds maximum model wall time, 100
read-only tool calls, 96 KiB cumulative unique evidence bytes, 24 KiB per
source file, and 256 KiB final output per attempt. Count projected/generated
evidence as well as source text toward the cap in A, and tool-returned evidence
in B; schema/instructions are reported separately. These are equal upper
budgets, not a requirement to consume the same amount. Input file truncation
must be explicit: record requested byte ranges and use UTF-8 safe boundaries.
Count the union of returned byte ranges per pinned file; repeated reads still
consume calls and wall time. Generated evidence is counted by unique serialized
UTF-8 bytes per evidence item, without deduplicating merely similar claims.
Report source and generated bytes separately; equal caps are not equal costs.

Record model input/output and cached tokens when available; no monetary cost
estimate may treat missing usage as zero. Token counts are observations rather
than unenforceable hard limits. Record total wall time including preparation,
validation, and retries separately. A cap or invalid output yields a failed
unit; no substitutions or unlimited retries. P56-T3 must demonstrate budget
enforcement before P56-T4. If the current arm cannot be bounded using a wrapper
without changing its logic, amend the protocol before any scored generation.
Use the existing provider constructor with explicit reasoning_effort="low";
the historical CLI's omitted setting is not a reproducible low-effort lock.

The T3 execution lock includes a machine-readable ledger schema: each tool
invocation has a sequential ID, source hash/range, returned bytes, monotonic
start/end times, and terminal status. Model wall time is the sum of request
durations through completion/timeout, including repair and failed retries.
Total generation wall time runs from snapshot preparation to final validation.
Retry only transport errors, timeout, or invalid output after the single repair;
never retry a valid but weak answer. All attempts share the repository caps.
Lock the current arm's input artifact hashes (including taxonomy and handoff),
exact provider parameters and environment versions before running either arm.

P56-T2/T3 artifacts must be versioned and their commit/digests recorded in a
pre-run execution lock before P56-T4. This fills implementation identities only,
not thresholds, targets, or answers. Model unavailability or changes to any
frozen condition require a new version before both arms run. Luna High agents
used to prepare this benchmark are research assistants, not experimental arms.

## Isolation and Blinding

An authoring worker receives only the generic authoring task, intended product
scope, allowed source snapshot, schema/templates, and its output directory.
It must not receive benchmark questions, answers, scores, or prior proposals.
Run it in an isolated filesystem containing only these inputs; a read-only
sandbox over the maintainer checkout is insufficient because the answer key
is committed there. Exclude parent conversation, personal skills, MCP mounts,
network access, evaluator files, and sibling arms from the worker environment.
Test denial of answer-key and sibling access before generation. This isolation
also applies to consumer evaluations with their respective input allowlists.
The execution lock includes a path-level input allowlist with hashes and a
denial-test receipt for answer-key, sibling-directory and network access.
T3 must refuse generation if any denial probe succeeds. Separate author,
consumer and scorer bundles; the custodian holds full receipts and label map.
Consumer source references retain repository/revision/path, not provider IDs.

Assign arm labels using a seeded permutation recorded in evaluator-only data
before review. Hide generation method, model receipts, and mapping from the
reviewer; retain provenance in an evidence view so claims remain verifiable.
Document that style may reveal authorship despite neutral labels. Do not
remove content to manufacture blindness. A separate custodian retains mapping.

## Consumer Evaluation

Run each of the 25 questions once per arm in a fresh session, using Spark at
low reasoning for all 75 answers. Give each session only that question and its
arm artifact, no reference answers or other arms. The first pass is artifact
only: 120 seconds, 16 read calls, 256 KiB artifact bytes, 16 KiB answer. No
additional sources are available. Allow no retries for a content failure.

After freezing first-pass answers, a second fresh session for every question
and arm can use the same artifact and pinned source tree, with the same limits
plus at most five source-file reads and 128 KiB source bytes. Run all 75
source-assisted answers regardless of first-pass score. Record additional reads,
bytes, time and tokens; never replace the artifact-only score with this score.
No code execution or package installation is permitted in either pass.

A maintainer scores the anonymized answers against evaluator references.
Automated scores may assist but must be labeled separately; the agent cannot
claim maintainer approval. Record manual correction minutes per package arm
and exact edits on a separate copy. Stop editing at 30 minutes per package;
unfinished correction counts as exceeding the budget, not as a fast edit.

## Scoring and Frozen Gates

Each reference lists two required facts. Score 2 only if both are correct,
1 if exactly one is correct, and 0 if neither is correct or a material
contradiction makes the answer unsafe to use. An explicit unknown can avoid an
unsupported claim but does not earn facts it cannot answer. Record every
material unsupported behavioral claim separately. A claimed source citation
must resolve to the pinned source and substantiate the associated fact.

Accept paraphrases preserving every qualifier in the canonical fact (including
optional, experimental and estimated); do not require literal phrasing.
General praise or stack names do not imply a behavior. A material contradiction
reverses a required fact or recommends a configuration/action contradicted by
its source. An unsupported material claim asserts behavior, compatibility,
security or licensing not established by the cited pinned evidence. Explicitly
attributed vendor claims are not independently measured guarantees. Required
source spans are recorded per question in the benchmark. Two scorers assess
independently; record agreement before a maintainer adjudicates disagreements
with a source-backed reason. Missing adjudication leaves evaluation pending.

Utility is sum(score)/50 for each arm and pass. Failed/missing generation or
consumer output scores zero for all affected questions; all five repositories
and 25 questions remain in denominators. Report category and per-repository
scores alongside totals. Never reward novel intent count or literal keywords.

Agent-first adoption requires all of the following:

- Five complete packages pass independent SpecPM validation; no missing unit.
- Artifact-only utility B >= 0.85 and B minus A >= 0.10, with B >= 0.70
  in each repository. With 50 integer fact points, 0.85 requires at least 43.
  Each question category must also score at least 0.70 across repositories.
- B minus README utility >= 0.05; alternatively B is no worse than README and
  its median artifact-only answer time is at least 20% lower. Missing timing
  cannot satisfy the alternative. Report tokens as a corroborating measure.
  The timing alternative requires complete nonfailed answers in both B and C
  and no per-repository utility regression; timeouts are not fast answers.
- No material unsupported behavioral claims in B, and all B citations resolve
  and support their associated facts after source review.
- Median maintainer edit time for B <= 10 minutes and no B package exceeds
  20 minutes. Failure or unreviewed units cannot pass this gate.
- Median generation wall time B <= twice A and total B generation <= 100
  model-wall minutes. Report source-assisted lookup counts and consumption
  costs for all arms, even when artifact-only gates pass.

All gates require maintainer sign-off. If unavailable, report pending human
evaluation. Failure selects diagnosis or stop, not automatic scale-out. Any
post-result prompt, model, or rubric change is a new labeled experiment.
Report the five paired repository deltas and leave-one-repository-out range
as a sensitivity check, not a confidence interval or population claim. This
small purposive sample cannot establish mass-corpus effectiveness.

## Reproducibility and Handoff

Record benchmark version/hash, source revisions and file hashes, authoring
artifacts, environment/tool versions, budgets consumed, terminal statuses,
validation reports, blinded answers, scorer identities and rubric decisions.
Keep raw model transport responses, prompts, hidden reasoning, secrets, and
machine paths out of portable evidence; normalized answers and candidate YAML
are intentional result artifacts. Source references are relative paths and
public repository URLs. Public methodology does not make the answer key an
allowed authoring input.

P56-T2 authors the skill against this contract. P56-T3 proves isolation and
bounded execution. P56-T4 generates only after their pre-run lock is complete.
