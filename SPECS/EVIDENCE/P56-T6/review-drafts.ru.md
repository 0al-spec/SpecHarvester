# P56-T6: пять черновиков ревью

**AI assistance only; maintainer confirmation pending.**

Это предложенные AI формулировки, а не уже полученные отзывы владельца.
Оцениваются **пять исходных кандидатов P56-T4**, до исправлений для каталога.
Главный пользовательский сценарий: найти пакет под свой intent, затем сравнить
capabilities, интерфейсы и ограничения. Спека не обязана заменять полный README.
Примеры запросов ниже иллюстрируют назначение, а не результаты поискового теста.

## openai/codex

**Пример intent:** «Встроить coding agent в приложение или запускать его из CLI».

**Черновик отзыва:** «Пакет помогает понять, что передо мной локальный coding
agent с CLI, TypeScript и Python SDK, а не просто библиотека на JavaScript.
Для первичного выбора полезны streaming, structured output, продолжение сессий
и работа с репозиторием. Но локальный запуск не означает локальную обработку
всех данных. Исходная спека недостаточно явно и неверным типом эффекта описывает
отправку данных удалённому сервису. Такой оригинал требует исправления».

| Вопрос T6 | Предлагаемая оценка оригинала |
| --- | --- |
| Назначение и пользователь | Понятны: разработчик или автор приложения, которому нужен coding agent. |
| Начало работы | Частично: есть установка и вход, SDK-примеры; подробного контракта `codex exec` нет. |
| Операции и настройки | Полезны working directory, environment, config overrides и resumption; полного эксплуатационного руководства нет. |
| Ограничения и эффекты | Существенная ошибка: `network_read` не отражает отправку prompts и возможных images/repository context удалённому provider. |
| Подтверждения | Частично: SDK evidence есть, но источник утверждения о logging не включён в исходную evidence-цепочку. |

**Сравнение:** README удобнее для установки, но не собирает SDK-детали в одном
месте. Проверенный старый principal package уже называл coding agent, но был
беднее по интерфейсам. Историческое AI-предложение отдельно уточняло CLI;
оно не было применено к старому YAML. Старый CLI scope уже нового CLI/SDK scope.

**Предлагаемая правка:** явно раскрыть outbound data flow, добавить отсутствующее
подтверждение logging и краткий noninteractive пример либо прямую ссылку на него.

Основания: [чтение кандидата](candidate-assistance.md#openai-codex),
[README и старые поверхности](reference-assistance.md),
[T4 findings](../../../docs/P56_T4_Five_Exploratory_Candidates.md#evidence-findings).
Ошибка эффекта также проверена в оригинале: `effects.sideEffects.network_call`.

## bitcoin/bitcoin

**Пример intent:** «Запустить собственный Bitcoin node с программным управлением».

**Черновик отзыва:** «Пакет правильно описывает Bitcoin Core как node, который
проверяет blocks и transactions, с RPC и необязательным wallet/GUI. Это помогает
отличить его от библиотеки или API чужого сервиса. Особенно полезны предупреждения
про доступ к RPC и изменение состояния wallet. Но по пакету нельзя оценить
ресурсы для эксплуатации или сразу воспроизвести первый RPC-вызов. В evidence
есть неточности, поэтому описание полезно для shortlist, но требует доработки».

| Вопрос T6 | Предлагаемая оценка оригинала |
| --- | --- |
| Назначение и пользователь | Понятны: оператор полноценного node, при необходимости с wallet/GUI. |
| Начало работы | Частично: запуск бинарников описан, получение сборки и законченный RPC-пример отсутствуют в просмотренном пакете. |
| Операции и настройки | Полезны `bitcoin.conf`, restart, data directory и выбор wallet endpoint. |
| Ограничения и эффекты | Есть важные предупреждения про RPC и wallet; disk/RAM, начальная синхронизация и эксплуатационные требования не установлены. |
| Подтверждения | Требуют исправления: диапазоны excerpts неточны, часть рекомендации об isolation не подкреплена упакованным источником. |

**Сравнение:** корневой README объясняет продукт и разработку, кандидат добавляет
эксплуатационные детали. Проверенный старый пакет оставался generic repository
metadata. Историческое AI-предложение описывало CMake/vcpkg, а не назначение node;
это отдельная, требующая review поверхность.

**Предлагаемая правка:** исправить evidence и неподдерживаемый interface kind;
добавить источник требований к ресурсам и первый RPC-пример. Не придумывать
числа и не превращать development snapshot в проверенный stable release.

Основания: [чтение кандидата](candidate-assistance.md#bitcoin-bitcoin),
[README и старые поверхности](reference-assistance.md),
[T4 findings](../../../docs/P56_T4_Five_Exploratory_Candidates.md#evidence-findings).

## rtk-ai/rtk

**Пример intent:** «Сократить вывод shell-команд, который читает coding agent».

**Черновик отзыва:** «Теперь назначение RTK выражено прямо: сокращать контекст
от вывода команд, а не предоставлять абстрактные API-контракты. Для выбора
полезны различия между filtering, command rewriting и passthrough. Хорошо,
что нет обещания фиксированной экономии всего счёта за модель. Однако один
исходный code excerpt изменяет поведение исходника. Назначение описано полезно,
но доказательную часть такого оригинала принимать без исправления нельзя».

| Вопрос T6 | Предлагаемая оценка оригинала |
| --- | --- |
| Назначение и пользователь | Понятны: разработчик с AI-agent workflow и большим объёмом shell output. |
| Начало работы | Частично: wrapper/proxy и agent init показаны, получение бинарника в packaged quick start не описано. |
| Операции и настройки | Полезны configuration, tracking, raw-output recovery и telemetry controls. |
| Ограничения и эффекты | Указаны зависимость от underlying tools, приблизительные savings и отсутствие authorization от одного rewrite; условия telemetry стоит раскрыть точнее. |
| Подтверждения | Существенная ошибка: runner excerpt меняет условную обработку newline; также есть проблемы range metadata и включения provenance в пакет. |

**Сравнение:** README уже содержательный и хорошо объясняет продукт; преимущество
кандидата здесь в структурированном выборе, не в объёме информации. Проверенный
старый YAML описывал не тот outcome. Отдельное историческое AI-предложение лучше
попадало в назначение, но было rejected и не исправляло старый пакет.

**Предлагаемая правка:** заменить изменённые excerpts точными цитатами с корректными
диапазонами, включить provenance и явно описать условия telemetry. Проверить
заявление о сохранении exit status отдельно от качества сжатия текста.

Основания: [чтение кандидата](candidate-assistance.md#rtk-ai-rtk),
[README и старые поверхности](reference-assistance.md),
[T4 forensic findings](../../../docs/P56_T4_Five_Exploratory_Candidates.md#evidence-findings).
Дефект excerpt относится к генерации спеки, а не к качеству самого RTK.

## axios/axios

**Пример intent:** «HTTP client для JavaScript с общими настройками и cancellation».

**Черновик отзыва:** «Пакет помогает быстро проверить, подходит ли Axios как HTTP
client для browser/Node.js: есть instances, interceptors, timeout, cancellation
и обработка ошибок. Это полезная карточка для сравнения, хотя README значительно
полнее и удобнее для изучения API. Исходник спеки ошибочно описывает сетевой
эффект только как чтение, несмотря на отправку request data. После исправления
карточка полезна; превосходство над альтернативными HTTP clients не показано».

| Вопрос T6 | Предлагаемая оценка оригинала |
| --- | --- |
| Назначение и пользователь | Понятны: JS/TS-разработчик browser или Node.js приложения. |
| Начало работы | Частично: import и первый GET есть, команда установки в packaged excerpt отсутствует. |
| Операции и настройки | Достаточно для первичного сравнения: defaults, instances, interceptors, timeout, response/error handling и cancellation. |
| Ограничения и эффекты | Существенная ошибка: `network_read` не описывает передачу headers/body и возможное изменение remote state запросами. |
| Подтверждения | Есть README, types и metadata; прежняя проверка hashes/ranges не нашла mismatch, но не доказывала правильность всех смысловых утверждений. |

**Сравнение:** старый principal package уже распознавал HTTP client, но не давал
этих API-деталей. README даёт больше примеров и security guidance. Историческое
AI-предложение уточняло request/response и module consumption, но оставалось
неприменённым proposal, а не доказательством работы транспорта.

**Предлагаемая правка:** корректно описать outbound data flow; для сравнения явно
показать существенные defaults и adapter/runtime limitations либо отметить их
как неизвестные. Не обещать встроенные retry/cache, исключённые из этой границы.

Основания: [чтение кандидата](candidate-assistance.md#axios-axios),
[README и старые поверхности](reference-assistance.md).
Ошибка эффекта проверена в оригинале: `effects.sideEffects.external_http`.

## n8n-io/n8n

**Пример intent:** «Собирать интеграционные workflows с visual editor и AI assistance».

**Черновик отзыва:** «Пакет показывает n8n как платформу автоматизации, а не как
небольшую SDK-библиотеку. Для shortlist полезны workflows, Instance AI, resource
tools и условия workflow building. Но подробности одной AI-подсистемы занимают
заметную часть описания. Нельзя читать capability о безопасной verification как
доказанную гарантию отсутствия внешних изменений. Пакет полезен для выбора,
если явно сохранить этот предел и отделить общую платформу от AI-функций».

| Вопрос T6 | Предлагаемая оценка оригинала |
| --- | --- |
| Назначение и пользователь | Понятны: команды, которым нужны интеграционные workflows и AI assistance. |
| Начало работы | Есть npx/Docker quick start; полного Instance AI HTTP route/payload контракта нет. |
| Операции и настройки | Полезны model/provider, MCP/search и sandbox configuration; это не полное руководство по production deployment. |
| Ограничения и эффекты | Видны state/database writes, code execution и network calls; simulation/isolation и разрешённый сценарий лицензии отдельно не доказаны. |
| Подтверждения | Есть документация подсистем; повтор document ID и форматирование license excerpt отмечены в T4. Runtime verification не выполнялась. |

**Сравнение:** корневой README лучше показывает общий продукт и быстрый запуск;
кандидат добавляет Instance AI детали. Проверенный старый principal package и
semantic proposal относятся к более узкому `@n8n/agents` SDK. Сравнение не
показывает, что новый пакет лучше всех 77 retained packages n8n.

**Предлагаемая правка:** явно различить core platform и условно доступные AI
возможности; обозначить verification как документированное поведение, не
испытанную гарантию. Исправить duplicate ID; условия лицензии не додумывать.

Основания: [чтение кандидата](candidate-assistance.md#n8n-io-n8n),
[README и старые поверхности](reference-assistance.md),
[T4 findings](../../../docs/P56_T4_Five_Exploratory_Candidates.md#evidence-findings).

## Что нужно от тебя

Можно ответить в чате по каждому пакету: **согласен с черновиком**, **поправка**
или **отложить**. Самое полезное уточнение: какой информации тебе всё ещё не
хватает, чтобы включить пакет в shortlist или отклонить его. Например:
«RTK: согласен, важнее показать совместимые agent integrations, чем установку».

Твоё подтверждение будет записано как **assisted review этого текста**, а не как
самостоятельное чтение YAML, исходников или всех baseline surfaces. Проверка
пяти исходных вопросов T6 не отменяется; неизвестные ответы останутся неизвестными.
Время личного чтения/правок укажем только если оно известно, иначе оставим пустым.
Утверждение всех черновиков само по себе не закрывает T6 и не разрешает публикацию.
